Custom API URL syntax

Once you have configured and tested your Custom API, the Custom API URL can be released to users for API requests. For successful requests, users must be given the configured base URL. The base URL consists of the following:

  • Protocol and Host - The URL begins with the standard protocol and host name. For example: https://client.data3sixty.com
  • Service Indicator - The Service Indicator for the Custom API is "services".
  • API ID - The API ID for the Custom API is "custom".

Given this information, the Custom API base URL would be:

https:// client.data3sixty.com/services/custom

 

You must also provide users with the configured Service, Endpoints, Versions, and URI Types names in order to query for specific data. The following table details the field values that must be provided:

Value Description
Service The Service is the value configured in the URI Segment field in the Service definition.
Endpoint The Endpoint is the value configured in the URI Segment field in the Endpoint definition.
Version The Version is the value configured in the URI Segment field in the Version definition.
URI Type Name The URI Type Name is the value configured in the Segment field in the URI Type definition.

 

For example, users are given the following information:

  • Protocol and Host: https://client.data3sixty.com
  • Service Indicator: services
  • API ID: custom
  • URI: AcmeInc
  • Endpoint: RiskCodes
  • Version: 1.5
  • URI Type Name: RiskValues

Based on these details, the Custom API URL is:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/RiskValue

This request returns all data in the RiskValues object.

 

Finally, you must ensure that users understand which URI Types are Singleton and which are Collections. If a user attempts to use a Singleton URI Type without specifying a filter value, they will encounter an error.
