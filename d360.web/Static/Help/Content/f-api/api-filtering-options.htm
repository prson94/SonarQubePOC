Advanced filtering options

There are advanced filtering options which you can use fine-tune data requests.

Tip: For all filter options, the query can be reversed by adding an exclamation point (!) just after the equals symbol (=).

String filter

To retrieve data where one field value matches a specified string, add a string filter.

The syntax is <field_name>=<value>

For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?TechCode=3T

Note: The supplied filter value must match the field data type. In other words, strings must be provided for Simple Text field types, decimal values for Decimal Number fields, and so on.

You can also specify a comma separated list of literal values. In this case, at least one of the values must match the field value. As with single string filters, data types of the supplied values must be the same as that of the field. When executing this type of filter, the values are logically OR’d together. For example, the following request is equivalent to saying "Return all data where the TechCode value is 3T OR 4T OR 9C:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?TechCode=3T,4T,9C

 

To reverse a string filter (in other words, return data that does not match the string), add an exclamation point just after the equals symbol. For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?TechCode=!3T,4T,9C

Prefix filter

You can also filter the request with a specified prefix filter.

The syntax is prefix(string)

For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?BusinessClass=prefix(Aviation)

This request would return all data starting with "Aviation" as well as "aviation" since no case-sensitivity is specified.

 

To reverse a prefix filter (in other words, return data that does not match the prefix), add an exclamation point just after the equals symbol. For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?BusinessClass=!prefix(Aviation)

Suffix filter

In addition to the prefix filter, you can filter items by suffix.

The syntax is suffix(string)

For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?BusinessClass=suffix(Aviation)

This request would return all data ending with "Aviation" as well as "aviation" since no case-sensitivity is specified.

 

To reverse a suffix filter (in other words, return data that does not match the suffix), add an exclamation point just after the equals symbol. For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?BusinessClass=!suffix(Aviation)

Case sensitive filter

You can filter API requests by case-sensitivity.

The syntax for this option is: match_casesens(case)

For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?BusinessClass=match_casesens(Aviation, aviation)

This request would return all matches to both "Aviation" and "aviation", unlike the following request which would only return matches to "aviation":

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?BusinessClass=match_casesens(aviation)

 

To reverse this filter (in other words, return data that does not match the case sensitivity specified), add an exclamation point just after the equals symbol. For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?BusinessClass=!match_casesens(aviation)

Suffix case sensitive filter

You can combine the suffix and case-sensitivity filters.

The syntax is: suffix_casesens(string)

For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?BusinessClass=suffix_casesens(Aviation)

This request would return results ending in "Aviation", but not those ending in "aviation".

 

To reverse this filter (in other words, return data that does not match the case sensitivity specified), add an exclamation point just after the equals symbol. For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?BusinessClass=!suffix_casesens(Aviation)

Prefix case sensitive filter

You can combine the prefix and case-sensitivity filters.

The syntax is: prefix_casesens(string)

For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?BusinessClass=prefix_casesens(Aviation)

This request would return results starting with "Aviation", but not those ending in "aviation".

 

To reverse this filter (in other words, return data that does not match the case sensitivity specified), add an exclamation point just after the equals symbol. For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?BusinessClass=!prefix_casesens(Aviation)

Range filters

You can specify ranges by using a simple syntax or by using a range function.

Simple range syntax

To request data filtered by a given range, a range may be provided with starting and ending numbers separated by two periods (..). For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?LastYearOfAccount=2004..2016

This would return data where the LastYearOfAccount field values were 2004 through to, and including, 2016. This type of filter is implicitly inclusive, that is, the results include data where the Last YearOfAccount field is 2004 and 2016.

To request data that is outside of the given range, prefix the ranges by an exclamation mark. For example:

https://client.data3sixty.com/services/custom/AcmeInc/RiskCodes/1.5/ RiskValues?LastYearOfAccount=!2004..2016

This would return data where the LastYearOfAccount field values were before 2004 and after 2016.

Range function

The Custom API also supports the use of a range function.

The syntax is range(N1,Q1,N2,Q2), where:

  • N1 is the start of the range
  • Q1 is a qualifier: either "incl" (to include the start value), or "excl" (to exclude the start value)
  • N2 is the end of the range
  • Q2 is a qualifier: either "incl" (to include the end value), or "excl" (to exclude the end value)

Some valid syntax examples are:

  • <date_field>=range(2017-01-01,incl,2018-05-07,excl)
  • <date_field>=range(2017-01-01,excl,2018-05-07,incl)
  • <number_field>=range(2,incl,10000000,excl)
  • <number_field>=range(100,incl,2000,incl)

The request can have any combination of qualifiers.

As with other filters, all of these requests can be reversed by including an exclamation point after the equals sign and before the values.
