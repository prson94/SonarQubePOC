Establishing quality rules

Note: If you are not already familiar with quality rules you should first check out the User Guide topics Introduction to assets and Quality rules.

 

It is the responsibility of the system administrator to define and maintain a set of quality rules, in order to enable Data Steward and Business Owner users to use these quality rules as a framework for collecting quality metrics from other systems and relating them to the artifacts governed by the system.

Dimensions

When organizations check data quality, they typically focus on the quality dimensions described below:

Quality Dimension

 Definition
Accuracy

A validation that compares data element values to a domain of expected, acceptable values or to expected ranges of values, or both.
Completeness

A validation that verifies that a source field is not empty when a value is required.
Conformity

A validation that verifies that data element values conform to an expected format, pattern, or encoding.
Consistency

A validation that verifies that a data element value is consistent with the value of another field or fields on the same record.
Duplication

A validation that verifies that a data element value is unique
Integrity

A validation that identifies missing data within relationship linkages
