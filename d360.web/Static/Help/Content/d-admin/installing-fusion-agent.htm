Installing the Fusion agent

The Fusion agent contains a series of connectors (.NET assemblies) that understand the target metadata location. For example, when requesting that the agent crawl a SQL Server database, the agent must have the SQL Server connector that understands the system metadata tables within SQL Server.

The following connectors are shipped with Infogix Data3Sixty:

  • 3DI
  • AWS Simple Storage Service (S3)
  • AWS Redshift
  • Bloomberg (Fields.csv and Lookup.out)
  • DB2 Database
  • Eagle PACE
  • Markit
  • Oracle Database
  • SQL Server Database
  • Sybase Database

It is also possible to create your own connector to work with a custom metadata store.

Server specifications

At a minimum, the server running the Fusion agent should contain the following:

Configuration Value
Server operating system Windows 2012, 2012 R2, or 2016
Processors 2 cores
Memory 4 GB RAM (minimum)
Software .NET Framework 4.5.1
Network requirements Web access, access to network resources like databases. This should be a machine on your local network / domain.
Port

443 (SSL over TLS 1.2)

Fusion uses this port configured via https to transmit metadata to your cloud instance of Infogix Data3Sixty.

Note: You may need to confirm firewall openings to ensure that the information can be transmitted.

Account permissions

The following permissions are required on the Windows account that is configured to run the fusion process:

  • Https access to your Infogix Data3Sixty site (i.e. https://<client>.data3sixty.com)
  • Read/write/execute access to the directory from which the fusion agent is being run. Write access is required to enable the Fusion agent log file to be updated.
  • Ability to log in as a batch job to enable the scheduled task to be configured to run when the current user is not logged in.
  • Access to log in to any of the configured data sources that you want to run Fusion for. For example, if you want to configure your Fusion agent to connect to a SQL Server database using trusted credentials, the account on which the Fusion agent is running needs access to the SQL Server database. Alternatively, you can specify the credentials to connect to the data source in the Fusion agent config file.

  • If you run the Fusion agent from the Windows program files folder, you must make sure that the account has the required permission to access the program files folder. For the scheduled task, this will require running the scheduled task with Run with highest privileges checked.

Oracle database permissions

When scanning SQL Server databases, the following permissions must be applied to the account that you are authenticating to the database with:

grant select any table to <user_name>;

grant select DBA_CONSTRAINTS to <user_name>;

grant select DBA_DB_LINKS to <user_name>;

grant select DBA_INDEXES to <user_name>;

grant select DBA_MVIEWS to <user_name>;

grant select DBA_OBJECTS to <user_name>;

grant select DBA_PROCEDURES to <user_name>;

grant select DBA_SEQUENCES to <user_name>;

grant select DBA_TAB_COLS to <user_name>;

grant select DBA_TABLES to <user_name>;

grant select DBA_TRIGGER_COLS to <user_name>;

grant select DBA_TRIGGERS to <user_name>;

grant select DBA_VIEWS to <user_name>;

grant select SYS.ALL_USERS to <user_name>;

SQL Server database permissions

When scanning SQL Server databases, the following permissions must be applied to the account that you are authenticating to the database with:

ALTER ROLE db_datareader ADD MEMBER <user_name>

GRANT VIEW SERVER STATE TO <user_name>;

GRANT VIEW DEFINITION TO <user_name>;

Downloading and configuring Fusion

  1. Download the Fusion agent to the server on which it will be run. You can download the agent from: https://d3s.blob.core.windows.net/agent/Agent2.0.zip
  2. Once the file has downloaded, right-click the zip file, select Properties from the context menu, then check the Unblock checkbox. Click OK.
  3. Unzip all files to a location on the server, and make a note of the physical path to the files.
  4. Locate your service account key and secret from Infogix Data3Sixty Support. The file is typically called "ApiInfo.txt". This file contains the url prefix, key, and secret you will need to set up the agent on the server.
  5. In order for the agent to connect to custom databases such as DB2, a set of vendor drivers must be installed on the server running the agent:
    DatabaseDriver download
    .NET 4.5.1

    If running the agent on a Windows 2012 server or higher, .NET 4.5.1 should be pre-installed. If not, please run the .NET installer by downloading the installer at the following link:

    https://www.microsoft.com/en-us/download/details.aspx?id=40773

    AWS Redshift

    If not already installed, download and install the Redshift ODBC drivers.

    For 32-bit: http://d3s.blob.core.windows.net/agent/AmazonRedshiftODBC32-1.3.7.msi

    For 64-bit: http://d3s.blob.core.windows.net/agent/AmazonRedshiftODBC64-1.3.7.msi

    DB2https://d3s.blob.core.windows.net/agent/ibm_data_server_driver_package_win64_v10.5.exe
    Sybasehttps://d3s.blob.core.windows.net/agent/Sybase_SQLA17_Windows_Client.exe

Configuring the scheduler

  1. Navigate to Windows Administrative Tools on the server.
  2. Double-click the Task Scheduler icon.
  3. In the Task Scheduler, right-click the Task Scheduler List folder in the sidebar. Select New Folder from the context menu.
  4. Name the folder Infogix Data3Sixty.
  5. Right-click the new Infogix Data3Sixty folder in the sidebar and select Create Basic Task.
  6. Name the task Fusion Agent, then click Next.
  7. Select Weekly for the frequency selection, then click Next.
  8. Select the required days, then click Next.
  9. Select the path to the folder containing the Fusion agent, ensuring that you select the executable named d360.agent.task.exe.
  10. In the Add Arguments field, provide the following values, separated by a space:

     

    ENVIRONMENT_NAME API_KEY API_SECRET

     

    For example:

    demo 12345 hgh5$3j2u26

    Tip: You will find the key and secret from the "API Info.txt" file that you received from Infogix Support.

     

  11. Click Next, then confirm your settings and click Finish.
  12. Right-click the newly created Fusion Agent task, and select Properties.
  13. Select the Triggers tab, then edit the schedule trigger settings to match the following:

  14. Click OK, then select the General tab.
  15. Select Run whether user is logged on or not. This is required to ensure that the Fusion agent runs regardless of whether or not the current Windows user is logged in. Click OK.

The Fusion agent should now be configured to run for your environment. As a test, after two minutes there should be a newly created file called AgentLog in the folder where the agent executable is located.
