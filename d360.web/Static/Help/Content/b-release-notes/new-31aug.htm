New features and enhancements

Workflows

Feature Tracking number

Workflow default notification

  

When creating a workflow with an Email Notification or Form activity, you can specify a user or a responsibility to receive email notifications. Previously, if users in the role specified on a workflow step were not found, the notification would instead be sent to all administrators.

There is now a new workflow setting on the Administration > Settings page that allows administrators to specify a user group to send workflow emails and assignments to when users in the role specified on a workflow step are not found. The default is to notify all administrators.

 

See Customizing the application.

GOV-4701

Bulk respond to assignments

  

A number of workflow improvements have been made in this release to simplify the process of responding to workflow tasks that are assigned to you.

The Your Assignments panel includes the following information to help you select which items to respond to; the name of the workflow that generated the assignment, the version of the workflow, the workflow step, and the number of forms that you need to complete for a selected workflow step. If you have a large number of items assigned to you, the Your Assignments panel breaks down the list of items into multiple pages, rather than showing one long list.

If there are a large number of tasks assigned to you, you can save time by responding to multiple items relating to the same workflow step at once.

If you hover over items in the Bulk Respond grid, you will see details of the asset that the workflow has been raised on, including the artifact type, fields and the asset ID. For workflows that are based on action types, hovering over the information icon shows the action details including the information provided by the user who completed the action form. Above the Bulk Respond grid, you can find information about the workflow version, the workflow step, the object e.g. Artifact or Issue, and the object type e.g. Business Term or Data Quality Issue.

See Your assignments.

 GOV-4147

 

Form activity email notification

  

When administrators are defining a workflow, there is now an option to include the information from any forms completed in a previous step of the workflow in the form email.

This adds to the existing functionality that allows administrators to include previous form responses when configuring the Email Notification activity.

See Setting up a form.

 GOV-4314

Email Activity backup responsibility

  

To expand on the existing functionality available when configuring a Form activity, administrators can now also add a backup responsibility when configuring an Email Notification activity. This means that the system will initially look for users assigned to the first responsibility, but if there are no users assigned to that responsibility, the system will look for users assigned to the second responsibility and send the email to them.

See Establishing workflows.

Corrected issues

Issue summary Issue number

Bulk loading relationships

  

Resolved an issue where cardinality relationship rules were not being enforced when bulk loading objects with relationships. For example, for a relationship with a cardinality of one to one (for example, one artifact fuses with a specific fusion attribute), it was possible to ignore the one to one cardinality rule and treat this as a one to many relationship via bulk loading.

 GOV-4059

Scoring

  
The scoring engine has been corrected to properly retrieve and process raw metrics that are sent to Infogix Data3Sixty Govern from Infogix Data3Sixty Foundation. GOV-4877

Fusion attributes

  

Resolved an issue on the Fusion page to ensure that the Relationships panel displays the corresponding objects for relationship types with a value of 1 or more for a selected Fusion attribute.

 GOV-5088

Workflow Timer transition

  

An issue has been addressed to ensure that the Timer transition only runs at the configured frequency, rather than running every fifteen minutes.

 GOV-5198
   

Resolved an error which was encountered when a Timer transition type was used when the target step was not followed by a subsequent step. The Timer transition type is primarily used to send reminder emails when a Form step has not been completed.

 GOV-5199

Deleted items

  
Resolved an issue where deleting an object from the application did not remove the responsibilities for the item which were then counted in the Community page, resulting in inaccurate counts and unnamed items appearing in the Community Items Owned panel and on a user's Resource page. GOV-5222

List field display value

  

Resolved an issue with List field types where list items would not be displayed if a special character was present in the display value and multi select was enabled.

 GOV-5225

Rule names

  
Previously, when a rule was deleted a new rule could not be added with the same name as the deleted rule. It is now possible to create a new rule with the same name as a deleted rule. GOV-5241

REST API documentation

  
Navigating to Administration > API now correctly takes you to the Swagger API documentation where you can test out the various REST endpoints. GOV-5259

Fusion rules

  

Resolved an issue with Fusion rules causing items to be duplicated. This issue occurred when items that required a parent item to be promoted to the system were promoted even if a parent item was not found.

 GOV-5260

UID in item tooltips

  
The UID field is now only shown in tooltips for items that have this value. GOV-5286

Images in Html/Richtext fields

  
Previously when inserting an image into a Html/Richtext field, additional text was needed for the image to display. Now, an image can be the only content in a Html/Richtext field and it will display properly without any additional text. GOV-5287

Action type assignments

  

Resolved an issue with the assignments grid where sorting by the Name column did not have any effect for action type objects.

 GOV-5294

Workflow monitor

  

On the Workflow Monitor page, the Email Notification step details incorrectly listed all current members of the specified email group or responsibility as recipients of the email, rather than listing only the users who were in the group at the time the email was sent. This issue has now been resolved and only those users who received the email are listed.
